## О проекте

Дипломный проект — WMS-система управления складом. Цель диплома — не готовый продукт,
а описание принципов проектирования ИС: от сбора требований до выпуска в прод.
Код — иллюстрация этих принципов, поэтому незавершённые модули допустимы.

## Стек и настройки

- Java 17, Spring Boot 3.4.2, Gradle (`gradlew.bat bootRun`, `gradlew.bat build` → `build/libs/SimpleWMS.jar`)
- Spring Data JPA, `spring.jpa.hibernate.ddl-auto=update` (схема создаётся из сущностей)
- PostgreSQL 16 в Docker: `docker compose up -d` (`docker-compose.yml`, пока только БД)
- Настройки: `application.properties` (общие) + `application-dev.properties` / `application-prod.properties`
- Параметры БД — переменные окружения `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`;
  локально читаются из `.env` (шаблон `.env.example`, сам `.env` в git не попадает)
- Профиль по умолчанию — `dev`
- Начальные данные: `SQL/migrations/V001…` (справочные) и `V002…` (демо, только dev) выполняются
  при каждом старте через `spring.sql.init` после создания схемы; скрипты идемпотентны
- Приложение запускать из корня проекта (пути к SQL-скриптам относительные)
- Spring Security (сейчас всё открыто: `permitAll`, CSRF выключен)
- Thymeleaf + Bootstrap-шаблон (`src/main/resources/templates`, `static`)
- Lombok, MapStruct 1.4.2
- Порт: 8080
- Подробно о запуске: `Project_Docs/Запуск_для_разработки.md`
- Архитектура и бизнес-процессы: `Project_Docs/Архитектура.md`

### Именование в БД

Hibernate/Spring переводит camelCase в snake_case, но аббревиатура в конце слова склеивается:
`productName` → `product_name`, `productID` → `productid`, `receivingLineID` → `receiving_lineid`.
Учитывать при написании SQL.

## Структура кода (`com.tynyany.simplewmsv2`)

| Пакет | Назначение |
|---|---|
| `controller` | MVC-контроллеры страниц и `RestApiController` (`/api/*`). Только приём запроса и подготовка модели, без бизнес-логики |
| `service` | Интерфейсы `XxxService` + реализации `DefaultXxxService`. Бизнес-процессы: `InventoryService` (остатки и журнал движений), `ReceivingProcessService` (приёмка), `PlacementService` (маршруты размещения) |
| `domain` | Перечисления: `ReceivingStatus`, `MovementType`, `PlacementRouteStatus` (код хранится в БД как int) |
| `config` | `WmsProperties` — настройки `wms.*` (системные ячейки приёмки/отгрузки) |
| `exception` | `WmsException` / `NotFoundException` и обработчики: `GlobalExceptionHandler` (страница error), `ApiExceptionHandler` (JSON) |
| `dto` | Проекции для native-запросов (`UnplacedStockRow`) |
| `repository` | Spring Data репозитории |
| `dao` | JPA-сущности `XxxEntity` (таблицы БД) |
| `entity` | Доменные модели и DTO для форм/JSON |
| `entity_mappers` | MapStruct-мапперы |
| `models` | Вспомогательные классы UI (cookie-уведомления, генерация кодов, расчёт веса/объёма) |
| `security` | Конфигурация Spring Security |

## Основной бизнес-процесс (реализован)

1. ERP → `POST /api/new_receiving` (JSON-накладная) → `receiving` + `receiving_line`
2. Старт приёмки (статус «В процессе») → ввод факта по строке
3. По строке: партия (`batches`) + движение (`stock_movements`, тип «Приемка») + остаток (`stocks`) в зоне приёмки (location 1)
4. Генерация маршрутов размещения по зонам (`placement_route`, `placement_route_line`)

Заглушки: заказы, отгрузки, сборка, перемещения, отчёты, вики.

## Соглашения

- Язык общения, комментариев, коммитов и документации — русский.
- Новые сущности: `dao/XxxEntity` + `entity/Xxx` + `repository/XxxRepository` + `service/XxxService` и `DefaultXxxService`.
- Удаление — мягкое, через поле `del`.
- Операции, меняющие несколько таблиц, — в сервисе с `@Transactional`.
- Статусы и типы — только через `enum` из пакета `domain`, без «магических» чисел.
- Бизнес-логика — в сервисах, не в контроллерах и не в конструкторах.
- Любое изменение остатка — только через `InventoryService` (он же пишет журнал `stock_movements`).
- Нарушение бизнес-правила — `throw new WmsException("понятное пользователю сообщение")`;
  в UI контроллер показывает его через cookie `alertMessage`, в API ответ `{"success":0,"message":...}`.
- Id системных ячеек — из `WmsProperties` (`wms.locations.*`), не хардкодом.
- Логирование — SLF4J (`@Slf4j`), не `System.out`.
- Новый сервис с бизнес-логикой — с unit-тестами (Mockito) в `src/test/.../service`.
- Изменения в коде делать в отдельной git-ветке, коммит — только по согласованию.
- После каждой сессии — запись в журнал ниже.

## План и решения

План доведения до рабочего состояния: [`Project_Docs/План_доработки.md`](Project_Docs/План_доработки.md).

Принятые решения (09.10.2026):
- Объём: полный складской цикл (приёмка → размещение → перемещение → заказ → комплектация → отгрузка) + остатки.
- Прод: Docker Compose (приложение + PostgreSQL).
- ERP: REST API, ERP имитируется тестовыми запросами.
- Схема БД: остаётся `ddl-auto=update`; ручные скрипты — в `SQL/migrations/`.

- [x] Бизнес-логика в конструкторах (`StockMovement`, `GenerationProductPlacementRoutes`) → в сервисы — этап 1
- [x] `System.out` → логгер (SLF4J) — этап 1
- [ ] Нет внешних ключей / JPA-связей между таблицами
- [ ] Тесты есть только для сервисов приёмки, размещения и остатков (этап 1); нет интеграционных тестов
- [x] Список приходов: вес/объём выводятся без округления (522.64996), в заголовке «м^2» вместо «м³» — этап 1

В среде Claude нет доступа к Maven Central/Gradle. Библиотеки берутся из кэша Gradle Andrew
(`~/.gradle/caches/modules-2/files-2.1`, доступ выдан), компиляция — `javac` с Lombok/MapStruct,

(библиотеки появятся в кэше).
