# Требования к системе SimpleWMS

## 1. Назначение

SimpleWMS — система управления складом (Warehouse Management System) для склада штучного товара
с адресным хранением. Система ведёт учёт остатков по партиям и ячейкам и поддерживает полный
складской цикл: приёмка → размещение → перемещение → резервирование заказа → комплектация → отгрузка.
Учётная система предприятия (ERP) передаёт в SimpleWMS справочники и документы и получает обратно
результаты приёмки и отгрузки через REST API.

## 2. Роли пользователей

| Роль | Код | Задачи |
|---|---|---|
| Администратор | `ADMIN` | учётные записи и сотрудники; все функции менеджера и кладовщика |
| Менеджер склада | `MANAGER` | справочники, зоны и ячейки, заказы и резерв, отчёты, загрузка данных из ERP |
| Кладовщик | `STOREKEEPER` | приёмка, размещение, перемещение, комплектация, отгрузка |
| ERP (внешняя система) | `API` | загрузка справочников и документов, выгрузка результатов (ключ `X-API-Key`) |

| Заказы клиентов | ✔ | ✔ | — | — |

## 3. Функциональные требования

### 3.1. Справочники

| № | Требование |
|---|---|
| ФТ-01 | Ведение товаров: код, наименование, вес и объём единицы, внешний и внутренний штрихкод, категория, поставщик, ABC-класс, признак учёта срока годности |
| ФТ-02 | Ведение поставщиков и клиентов (код, наименование, контакты, адрес и часы приёма у клиента) |
| ФТ-03 | Ведение зон хранения и ячеек; адрес ячейки «зона-ряд-x-y-z», вместимость в литрах; системные ячейки приёмки и отгрузки |
| ФТ-04 | Загрузка справочников из ERP с созданием или обновлением по коду |

### 3.2. Приёмка

| № | Требование |
|---|---|
| ФТ-05 | Загрузка приходной накладной из ERP; повторная загрузка того же номера отклоняется, пока прежняя накладная не отменена |
| ФТ-06 | Приёмка по строкам: фактическое количество, срок годности (обязателен для товаров с учётом срока), ячейка размещения (необязательно) |
| ФТ-07 | Каждая принятая строка создаёт партию и остаток в зоне приёмки и запись в журнале движений |
| ФТ-08 | Исправление ошибочно принятой строки (возврат) и отмена накладной с откатом остатка |
| ФТ-09 | Завершение приёмки только после обработки всех строк; печать ТОРГ-12 по фактически принятому |

### 3.3. Размещение и перемещение

| № | Требование |
|---|---|
| ФТ-10 | Автоматическое формирование маршрутов размещения: по одному на зону хранения; ячейка — выбранная при приёмке, иначе подбор по ABC-классу, свободному объёму и наличию того же товара |
| ФТ-11 | Исполнение маршрута кладовщиком с подтверждением каждой строки, возможна другая ячейка; печать листа размещения |
| ФТ-12 | Перемещение партии между ячейками хранения полностью или частично; перемещать можно только незарезервированное количество |
| ФТ-13 | Поиск товара по коду, части наименования или штрихкоду; просмотр содержимого ячейки |

### 3.4. Заказы и комплектация

| № | Требование |
|---|---|
| ФТ-14 | Загрузка заказа клиента из ERP и ручное создание заказа |
| ФТ-15 | Резервирование по правилу FEFO: ближайший срок годности первым, партии без срока — последними, просроченные партии не резервируются; дорезервирование недостающего |
| ФТ-16 | Отмена заказа до передачи в сборку со снятием резерва |
| ФТ-17 | Передача полностью зарезервированного заказа в сборку: маршрут комплектации в порядке обхода ячеек |
| ФТ-18 | Подтверждение сборки строки с фактическим количеством; недостача фиксируется; собранное перемещается в зону отгрузки |
| ФТ-19 | Печать сборочного листа |

### 3.5. Отгрузка

| № | Требование |
|---|---|
| ФТ-20 | Отгрузка собранного заказа: документ, списание из зоны отгрузки, статус заказа «Отгружен» |
| ФТ-21 | Печать ТОРГ-12 на отгрузку |
| ФТ-22 | Выгрузка отгрузок в ERP и подтверждение их получения |

### 3.6. Остатки и отчёты

| № | Требование |
|---|---|
| ФТ-23 | Состояние склада по товарам, по партиям и ячейкам, загрузка ячеек; фильтры по товару, зоне, ячейке, сроку годности; подсветка истёкших и истекающих партий |
| ФТ-24 | Журнал движений с фильтрами по периоду, типу движения, товару и партии |
| ФТ-25 | Отчёты за период: по отгрузкам (клиенты, товары, недогруз), по поставкам (поставщики, товары, расхождения), по работе сотрудников (сборка и размещение) |
| ФТ-26 | Сводка на главной странице: документы и маршруты, требующие действий, партии с истекающим сроком |

### 3.7. Интеграция с ERP

| № | Требование |
|---|---|
| ФТ-27 | REST API `/api/v1` в формате JSON: справочники, приходные накладные, заказы, отгрузки, статусы документов |
| ФТ-28 | Единый формат ответа и ошибок, проверка входных данных с указанием поля |
| ФТ-29 | Описание API (OpenAPI / Swagger UI) |
| ФТ-30 | Имитация ERP для проверки и демонстрации обмена |

## 5. Ограничения

- Склад одной организации; несколько складов и юрлиц не поддерживаются.
- Единица учёта — штука; упаковки и коэффициенты пересчёта не ведутся.
- Инвентаризация и корректировки остатков вне процессов (движения «Инвентаризация», «Корректирование»
  предусмотрены в справочнике типов) — вне объёма дипломного проекта.
- Схема базы данных создаётся и обновляется Hibernate (`ddl-auto=update`); внешние ключи на уровне БД не заданы,
  целостность обеспечивается сервисами.
